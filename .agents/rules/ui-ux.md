# STUDYFLOW AI — PREMIUM UI & MOTION RULESET

Apply these rules globally to the entire StudyFlow AI application.

The goal is a **premium, refined, Apple-inspired product experience**: minimal, elegant, fast, spacious, intuitive, responsive, and extremely polished.

Do NOT copy Apple's proprietary UI, branding, layouts, icons, or visual identity. Use only the general principles associated with high-quality Apple product design: **clarity, hierarchy, restraint, consistency, precision, accessibility, and purposeful motion.**

---

## 1. CORE DESIGN PHILOSOPHY

StudyFlow AI must feel:

* Premium
* Minimal
* Calm
* Intelligent
* Modern
* Spacious
* Fast
* Precise
* Consistent

Avoid the appearance of:

* Generic SaaS templates
* Bootstrap dashboards
* AI-generated website templates
* Excessive gradients
* Excessive glassmorphism
* Crowded dashboards
* Random animations
* Oversized UI
* Excessive colors
* Too many cards
* Heavy shadows

The interface should feel intentionally designed.

Every element must have a reason to exist.

Prefer **fewer, better-designed elements** over visual complexity.

---

# 2. VISUAL HIERARCHY

Every screen must immediately communicate:

1. Where the user is
2. What matters most
3. What actions are available
4. What changed
5. What the user should do next

Use three levels of information:

### Primary

Large, confident typography.

### Secondary

Medium-weight supporting information.

### Tertiary

Small, muted metadata.

Do not make every piece of text bold or visually important.

Use whitespace to create hierarchy instead of adding borders everywhere.

---

# 3. COLOR SYSTEM

Use a restrained neutral palette.

Primary appearance:

* White or near-white surfaces
* Very light gray backgrounds
* Deep charcoal primary text
* Muted gray secondary text
* Subtle borders

Use **one main accent color** consistently for:

* Primary actions
* Active navigation
* AI actions
* Important highlights
* Progress indicators

Use semantic colors only when meaningful:

* Green → success
* Red → error/destructive
* Amber → warning
* Blue/accent → information or AI

Do NOT use rainbow colors.

Do NOT give every feature its own color.

AI should have a subtle recognizable accent, but avoid the typical excessive purple/blue neon AI aesthetic.

---

# 4. DARK MODE

If dark mode exists, design it intentionally rather than simply inverting colors.

Use:

* Deep charcoal backgrounds
* Slightly lighter elevated surfaces
* Soft white text
* Muted secondary text
* Subtle borders

Avoid pure black backgrounds with pure white text everywhere.

Maintain the same visual hierarchy in both themes.

---

# 5. TYPOGRAPHY

Typography is a primary part of the product experience.

Use a modern system font stack.

Prioritize:

* Readability
* Clear hierarchy
* Comfortable line height
* Appropriate letter spacing
* Limited font weights

Hierarchy:

### Hero

Large, confident, restrained.

### Page title

Large and clear.

### Section title

Medium/large.

### Body

Comfortable reading size.

### Metadata

Small and muted.

Avoid:

* Decorative fonts
* Excessive bold
* ALL CAPS everywhere
* Excessive italics
* Tiny text
* Too many font sizes

Typography should feel calm and premium.

---

# 6. SPACING

Use a consistent spacing scale throughout the application.

Prefer generous whitespace.

Do not compress unrelated controls together.

Use whitespace to separate:

* Sections
* Content groups
* Primary and secondary actions
* Navigation
* Data

The interface should feel spacious even when the page contains substantial information.

---

# 7. CARDS

Cards should be subtle and functional.

Preferred:

* Clean surface
* Small/subtle border
* Soft shadow only when necessary
* Consistent radius
* Generous internal padding

Avoid:

* Huge shadows
* Thick borders
* Excessive gradients
* Extremely rounded bubble cards
* Every element being placed inside a card

Not everything needs a card.

Use cards to group related information.

---

# 8. BORDER RADIUS

Use a consistent radius system.

Suggested:

* Small controls: 8–10px
* Buttons/inputs: 10–14px
* Cards: 14–18px
* Large feature surfaces: 20–24px

Use pill shapes mainly for:

* Tags
* Status labels
* Filters
* Compact controls

Do not make every component a pill.

---

# 9. SHADOWS

Shadows should communicate elevation, not decoration.

Use:

* Soft
* Large blur
* Low opacity

Avoid heavy black shadows, neon glows, and multiple stacked shadows.

If a component only looks good because of its shadow, redesign it.

---

# 10. BUTTONS

Buttons must feel tactile and premium.

### Primary

Strong hierarchy, clear label, comfortable padding.

### Secondary

Quiet and restrained.

### Destructive

Clearly communicate risk without dominating the interface.

Every interactive button needs:

* Default
* Hover
* Active/pressed
* Focus
* Disabled

Hover should be subtle.

Pressed state can use a very small scale change such as 0.98–0.99.

Never use dramatic button animations.

---

# 11. INPUTS

Inputs must be clean and easy to understand.

Use:

* Clear labels
* Comfortable height
* Consistent radius
* Subtle border
* Strong but restrained focus state

On focus, smoothly transition the border/accent.

Avoid excessive glowing inputs.

Validation must be clear and close to the relevant field.

---

# 12. NAVIGATION

The sidebar should feel like premium productivity software.

Navigation:

StudyFlow AI

Dashboard
Tasks
Study Planner
AI Copilot
Quiz Generator
Progress

Settings

Active navigation should be obvious but subtle.

Use:

* Soft active background
* Accent indicator when appropriate
* Consistent icon
* Consistent spacing

Do not make active navigation visually overwhelming.

On mobile, use a compact drawer or bottom navigation.

---

# 13. DASHBOARD

The dashboard should feel like an academic command center, not a collection of widgets.

Top:

**Good morning, [Name]**

Supporting context below.

Then prioritize:

### Today's Focus

Most important tasks.

### Upcoming Deadlines

Next relevant deadlines.

### Progress

Simple visual summary.

### AI Recommendation

Useful AI-generated recommendation.

Use visual rhythm:

**large → medium → small → whitespace**

Avoid filling every empty area with cards.

---

# 14. AI VISUAL LANGUAGE

AI functionality should have a consistent visual identity.

Examples:

✨ Generate Study Plan
✨ Break Down Task
✨ Ask AI
✨ Generate Quiz
✨ AI Recommendation

AI controls should feel integrated into the application.

Avoid giant glowing AI buttons or unnecessary futuristic effects.

The AI should feel intelligent and useful rather than decorative.

---

# 15. MOTION PHILOSOPHY

Motion must communicate something.

Every animation should answer at least one:

* Where did this come from?
* Where is it going?
* What changed?
* What can I interact with?
* Did my action succeed?

If an animation has no useful purpose, remove it.

Motion should feel physical, natural, and responsive.

Never animate simply because an animation is possible.

---

# 16. MOTION TIMING

Use short transitions.

Recommended:

* Micro interaction: 100–180ms
* Button/input: 120–200ms
* Card transition: 180–280ms
* Modal/drawer: 220–350ms
* Page transition: 200–400ms

Never make the interface feel slow.

Do not use fake delays just to make an animation visible.

---

# 17. EASING

Prefer natural easing.

Use smooth ease-out for entering elements and ease-in for exiting elements.

Use cubic-bezier curves where appropriate.

Avoid linear movement for normal UI interactions.

Avoid excessive bouncing or elastic effects.

Premium motion should feel controlled.

---

# 18. PAGE TRANSITIONS

Use subtle page transitions:

* Fade
* Slight vertical movement
* Small opacity transition

Example:

opacity 0 → 1

and

translateY(6px) → translateY(0)

Keep movement subtle.

Never make an entire page dramatically fly or rotate.

---

# 19. MODALS

Opening:

1. Background fades slightly
2. Modal appears from approximately 98% scale to 100%
3. Content becomes visible

Closing reverses the process.

Do not use dramatic zoom animations.

Modal interaction must remain fast.

---

# 20. DROPDOWNS

Dropdowns should feel attached to their trigger.

Use:

* Short fade
* Small vertical movement
* 150–220ms transition

Avoid bouncing.

---

# 21. TOASTS

Toast messages should be small and unobtrusive.

Examples:

**Task completed**

**Study plan saved**

**Unable to generate quiz**

Use subtle fade + vertical movement.

Never cover large portions of the interface.

---

# 22. TASK COMPLETION

When a task is completed:

1. Checkbox responds immediately.
2. Task state transitions smoothly.
3. Text becomes visually secondary.
4. Progress updates.
5. Optional subtle success feedback.

Do not use confetti for ordinary task completion.

Reserve celebrations for meaningful milestones.

---

# 23. PROGRESS ANIMATION

Progress bars and charts may animate when first appearing.

Example:

0% → actual value

Use a smooth transition.

Do not continuously animate charts.

Motion should stop once the value reaches its final state.

---

# 24. AI GENERATION EXPERIENCE

When Gemini is generating a study plan, quiz, or analysis, provide an elegant loading state.

Example:

**Analyzing your schedule**

↓

**Balancing subjects**

↓

**Creating your plan**

↓

**Your study plan is ready**

Use subtle motion.

Do not create fake delays. If Gemini responds quickly, display the result quickly.

---

# 25. STAGGERED CONTENT

Lists may use subtle staggered entrance animations.

Example:

Item 1 → 0ms
Item 2 → 30ms
Item 3 → 60ms
Item 4 → 90ms

Keep total delay short.

Do not make users wait for content that is already available.

---

# 26. HOVER

Hover effects must be subtle.

Cards:

* Slight elevation
* Slight border/background change

Buttons:

* Slight background change

Navigation:

* Soft highlight

Never:

* Rotate cards
* Dramatically scale components
* Add neon glow
* Move elements excessively

---

# 27. PRESS FEEDBACK

Clickable elements should respond immediately.

Buttons can use a subtle:

`scale(0.98–0.99)`

during press.

The effect should be barely noticeable but make the interface feel tactile.

---

# 28. SCROLL

Scrolling should remain natural.

Do not hijack browser scrolling.

Do not implement unnecessary scroll-jacking.

Sticky navigation may be used when useful.

Sticky elements should transition smoothly between states.

---

# 29. LOADING STATES

Never leave users looking at a blank screen.

For database-driven areas, use skeleton loading.

Skeletons should be:

* Subtle
* Lightweight
* Similar to final content structure

Avoid excessive shimmer.

For actions such as saving, use small inline progress indicators.

---

# 30. EMPTY STATES

Empty states should feel intentional.

Example:

### No tasks yet

"Your academic workspace is ready."

"Create your first task to start building your workflow."

Button:

**Add Task**

Use simple iconography when useful.

Never make an empty state feel like an error.

---

# 31. ERROR STATES

Errors must be calm, clear, and actionable.

Example:

### Something went wrong

"We couldn't generate your study plan."

Button:

**Try Again**

Never expose raw stack traces, database errors, API keys, or technical implementation details.

---

# 32. AI RESPONSE PRESENTATION

Never dump raw Gemini text into a giant paragraph.

Transform AI output into structured UI:

* Headings
* Lists
* Steps
* Cards where useful
* Highlights
* Metadata
* Clear sections

AI output should look like a native part of StudyFlow AI.

---

Charts should be:
* Minimal
* Clean
* Readable
* Consistent with the design system

* 3D charts
* Excessive labels
* Excessive colors
* Decorative chart effects
